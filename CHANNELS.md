# Guarded channels and shared defence

All endpoints authenticate with the existing gateway key. Providers must support the
endpoint and model requested. `GET /v1/znyx/channels` reports this key's configured
channel families; extractor configuration does not assert that the service is healthy.

| Channel | Gateway endpoint | Inspection and delivery |
|---|---|---|
| Chat | `/v1/chat/completions`, `/v1/messages` | Existing text/tool checks plus actual image, document and audio bytes |
| Embeddings | `/v1/embeddings` | Text checked/redacted before embedding; vectors returned in provider shape |
| Responses | `/v1/responses` | Inline history, instructions, text, media and function/custom tools; JSON or rebuilt buffered SSE |
| Images | `/v1/images/generations`, `/v1/images/edits` | Prompt and uploaded media checked; generated bytes OCR checked before release; buffered completion events |
| Speech | `/v1/audio/speech` | Input text checked; generated audio transcribed offline and checked before binary delivery |
| Transcription/translation | `/v1/audio/transcriptions`, `/v1/audio/translations` | Uploaded audio inspected before forwarding; returned transcript checked, including words/segments; JSON, text, SRT, VTT or buffered SSE |
| Realtime | `/v1/realtime?model=...` WebSocket | OpenAI GA events, manually committed audio, entire output turn checked before events are released |
| MCP | Existing `/v1/mcp/{server}` | Text and actual binary image/audio/document resources checked |

Azure providers use the corresponding `/openai/deployments/{deployment}/...` HTTP routes
and their configured API version. Realtime WebSocket currently uses the OpenAI format.
WebRTC, SIP, direct browser ephemeral credentials and other providers' native live protocols
are not implemented. Native speech SSE is refused; SDK binary streaming receives buffered
checked audio. Realtime requires mono PCM16 at 24 kHz, disables automatic VAD and provider
input ASR, and uses the local transcript for inspection. It does not emit provider input-ASR
transcript events. Use the guarded transcription endpoint when a transcript is required.

Responses require complete inline context and force `store: false`. Stored item/file IDs,
previous response/conversation references, background calls, opaque reasoning payloads,
provider-hosted tools and unknown content parts are refused. Supply inline media and
customer-governed tools instead. Full output contracts use Chat or Responses; Realtime
refuses a complete output contract rather than streaming an unvalidated contract.

## Offline media service

Install `znyx` and `znyx-inference[media]`, then run `znyx serve --ml`, or build the
`znyx-media` Docker target. Mount a local faster-whisper model directory with its tokenizer
and configuration, set `ZNYX_SPEECH_MODEL_PATH` and set `ZNYX_SPEECH_MODEL_SHA256` to the
approved `model.bin` digest. The model directory should be a read-only customer-owned mount.
Every model process verifies the digest before loading; extraction never downloads weights.
Tesseract must be installed (included in the media image; English OCR by default).

An existing private service can be selected with `ZNYX_MEDIA_EXTRACT_URL` or
`ZNYX_INFERENCE_URL`. It must pass the operator's in-network and policy egress checks.
Keep this service private; it processes raw media inside the customer's network.

Supported extraction: UTF-8 text/JSON/XML, single-frame Pillow-supported images, PDFs
(text layer and rendered-page OCR), DOCX/XLSX/PPTX (XML and embedded-image OCR), and
PyAV-supported audio with an installed offline speech model. Macros, embedded Office
objects, unsupported types and incomplete extraction are refused. OCR/ASR accuracy depends
on the document, language and approved model; these checks do not implement general visual
image moderation. A required redaction of extracted text withholds the binary object.

Bounds: 8 MiB per object, 32 attachments per call, 12 million pixels per image/rendered PDF
page, 8 PDF pages, 120 seconds of decoded audio, 1 MiB of extracted text, 1,000 Office ZIP
entries and 8 MiB total ZIP expansion. The service runs two extraction workers with a
150-second deadline; timed-out work retains its slot until it actually finishes. HTTP
provider outputs and realtime turns are bounded at 16 MiB; realtime frames at 1 MiB,
idle time at five minutes and sessions at one hour. Gateway request limits still apply.

Remote media needs exact HTTPS hosts in `ZNYX_MEDIA_URL_ALLOWLIST` and its region in
`ZNYX_MEDIA_URL_REGION`. Redirects, non-public DNS destinations, credentials and non-443
ports are refused. Downloads pin the checked public IP with the original TLS identity;
the provider receives the inspected bytes instead of a mutable URL. Inline bytes avoid
this additional network permission entirely.

`settings.media_inspection` defaults to `true`. Setting it to `false` explicitly restores
the legacy `uncheckable_content` allow/block behavior on Chat/MCP. New media endpoints
always require inspection. Parallel input forwarding never bypasses media inspection.

## Prices and budgets

Configure the model's rates through Gateway > Prices or `prices` in `gateway.yaml`.
The normal `input_per_mtok` and `output_per_mtok` remain required. Additional rates are
`per_image`, `per_audio_minute`, `per_million_characters`, `audio_input_per_mtok`,
`audio_output_per_mtok` and `cached_audio_input_per_mtok` (all in USD).

Images reserve requested count, transcription reserves inspected duration, and speech
reserves input characters. Their keys support spend limits; token-limited keys are refused
on media-unit endpoints. Realtime uses provider text/audio token breakdowns and needs
audio token rates before a spend-limited voice turn is admitted. Each response reserves
capacity before generation. Missing final usage on disconnect retains the conservative
reservation and marks usage estimated. Withheld provider output is still charged.
Unpriced calls without a spend limit report unknown cost rather than invented savings.

## Shared defence protocol

Participation is organization-wide, requires `org:write`, and is off by default. Scoped
project/environment keys cannot enable it. Only runtime credentials with `telemetry:write`
can ingest contributions; only a super-admin can publish or withdraw a fingerprint.
Participation and review actions are audited.

The exact outbound schema is:

```json
{"version":1,"digest":"<64 lowercase hexadecimal characters>","category":"prompt_injection"}
```

Categories: `prompt_injection`, `jailbreak`, `exfiltration`, `malicious_tool`. Runtime
contributions come from local blocking injection/jailbreak/exfiltration findings. A digest
is SHA-256 of `znyx-defence-nfkc-v1\0` plus NFKC-normalized, case-folded, whitespace-folded
UTF-8 text. Matches are exact normalized full-text fingerprints, not arbitrary executable
patterns or generalized attack detection. Extra fields and unknown versions are rejected.
No prompt/response, tool arguments, detector message or user identifier is transmitted.
Hashes still disclose that a known attack occurred; consent explains this.

Inventory > Shared defence shows received contributions, the signed feed and hash-only
false-positive/confirmed-attack feedback. Locally, the approver-only
`GET /v1/znyx/defence/contributions?cursor=0` returns up to 500 records and a `next_cursor`;
repeat with that cursor to inspect every record. `shared-defence.history` alongside the
governance spool holds the append-only history. Persist it on customer storage and apply
the customer's retention policy. Turning participation off discards queued unsent records
without sending and removes feed use after the next signed control update. Previously
published fingerprints remain until operator withdrawal.

Operators review oldest pending contributions under Admin > Shared defence, inspect
aggregated feedback, publish and withdraw. Feeds are bounded at 10,000 active signatures,
signed through existing bundle-set controls and polled normally (default 30 seconds).
They expire within two hours offline. Feed revisions invalidate cached input verdicts;
expiry and renewal also invalidate them even when signature contents are unchanged.
Realtime sessions require reconnecting after a defence-state change to recheck old context;
streamed output is buffered while shared defence is active. A proposed four-hour response
target requires staffed review and connected runtimes; it is not an automated SLA.
The network spans organizations on the same control plane. Separate self-hosted control
planes do not federate fingerprints automatically.

## Operated delivery

See [deploy/operated/README.md](deploy/operated/README.md). The customer owns infrastructure,
secrets, access grants and audit retention. Azure is the first target, with AKS access/audit
templates, Entra PIM activation and native marketplace packaging inputs. AWS EKS access is
retained. Helm/Terraform deployment and immutable review packaging are included. Seller
registration, authenticated CNAB build/upload, cloud validation and publication happen in real accounts.
Phase 6 traffic canaries, replay and automatic rollback remain independent work.
